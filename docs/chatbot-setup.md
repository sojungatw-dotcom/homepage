# OVE 등록형 챗봇 설정

## 구현 범위

- 홈페이지 8개 루트 페이지의 오른쪽 아래 채팅 버튼. 하위의 독립 오륙도 카드 덱은 제외합니다.
- 시작 메뉴: 포트폴리오 보기 / 제작물 보기 / 제작과정 / SNS 문의.
- 등록된 JSON 답변·질문·키워드·버튼·다음 단계만 사용합니다. 외부 AI API와 SDK 의존성은 없습니다.
- 한국어·영문 정규화 후 질문 완전 일치 우선, 가장 긴 키워드 포함 일치 다음 순서입니다. 동일 길이는 현재 단계의 다음 선택지를 우선하며 그다음 JSON 등록 순서입니다. 일치하지 않으면 지정된 fallback 안내입니다.
- 이전으로는 실제 방문 단계로 이동하고, 처음으로는 기록을 유지하며 시작 메뉴로 이동합니다. 대화 초기화는 대화·분기·문의 초안과 sessionStorage 항목을 삭제합니다.
- 같은 탭의 새로고침과 같은 출처 내 페이지 이동에서 sessionStorage로 이어집니다. 별도의 탭과는 동기화하지 않습니다. 최근 100개 메시지와 100개 방문 단계를 유지합니다.
- 문의 폼의 이름·이메일·문의 내용·동의는 sessionStorage에 저장하지 않습니다. 자유 질문에 직접 입력한 내용은 대화 기록에 포함됩니다. 문의 개인정보는 전용 폼에 입력하도록 안내하세요.
- 파일을 더블클릭하는 file:// 대신 HTTP 서버로 실행해야 JSON을 불러올 수 있습니다.

## 답변 수정

`data/chatbot.json`의 `nodes`에 항목을 관리합니다.

```json
{
  "sample": {
    "answer": "등록된 안내입니다.",
    "questions": ["사용자가 입력할 대표 질문"],
    "keywords": ["특정 키워드"],
    "buttons": [
      {"label": "다음 안내", "next": "works"},
      {"label": "콘텐츠 페이지", "href": "contents.html"}
    ]
  }
}
```

`next`는 실제 노드 ID여야 합니다. 버튼 링크는 내부 HTTP(S) 주소와 외부 HTTPS 주소만 허용합니다. 답변과 사용자 입력은 HTML로 해석하지 않고 텍스트로 표시합니다. `ui`는 제목, 공통 버튼, 입력 안내, 문의 폼 문구입니다. `fallback.answer`는 사용자가 지정한 문구를 그대로 유지합니다.

## Supabase 연결

현재 프로젝트 URL과 공개 키를 전달받지 않았으므로 실제 DB 연결과 테이블 생성은 아직 수행하지 않았습니다. 연결 전에도 안내 챗봇은 작동하고 문의 접수는 준비 중으로 표시됩니다.

1. 사용할 Supabase 프로젝트의 SQL Editor에서 `supabase/chatbot-inquiries.sql`을 실행합니다.
2. `data/chatbot-config.json`에 다음 값을 입력합니다.
   - `supabaseUrl`: 프로젝트 URL (`https://프로젝트.supabase.co`).
   - `publishableKey`: 공개용 publishable key 또는 legacy anon key. service_role/secret key는 절대 넣지 않습니다.
   - `rpc`: 기본값 `submit_chatbot_inquiry`.
   - `privacy.controller`: 실제 개인정보 처리자 이름/조직.
   - `privacy.contact`: 개인정보 문의용 연락처.
   - `privacy.retention`: 실제 운영할 보유·이용 기간과 삭제 기준.
   - `consentVersion`: 동의 문구를 바꿀 때 갱신할 버전.
3. URL, 공개 키와 개인정보 안내 3개 필드가 채워지면 폼 접수가 활성화됩니다. 이름·이메일·내용 입력과 동의 체크가 모두 필요합니다.
4. 본인 테스트 문의로 접수 후 Supabase Table Editor → `chatbot_inquiries`에서 확인합니다. `status`는 new / in_progress / closed로 운영할 수 있습니다.

브라우저는 저장용 RPC만 호출합니다. 테이블에는 RLS가 켜져 있고 방문자에게 직접 조회·수정·삭제 권한을 부여하지 않습니다. RPC는 입력 길이·이메일·동의를 검증해 행을 추가하며 개인정보를 반환하지 않습니다. 접수 시간과 동의 시간은 DB 시각으로 저장합니다. 성공 응답 때만 완료를 표시하고, 실패하면 입력 내용을 유지합니다. 동일 내용의 불확실한 네트워크 재시도는 같은 request_id로 중복 저장을 방지합니다(현재 폼을 유지하는 동안). 새로고침·화면 이동 후에는 초안과 재시도 ID를 보존하지 않습니다.

이 SQL은 보유 기간별 자동 삭제 작업을 생성하지 않습니다. 실제 보유 정책에 맞게 관리자 삭제 또는 예약 삭제를 별도로 설정해야 합니다. 공개 폼을 본격 운영할 때는 Supabase Edge Function 등의 서버 측 속도 제한과 봇 방지 적용을 검토하세요.

공식 참고: [API 키](https://supabase.com/docs/guides/getting-started/api-keys), [DB 함수와 실행 권한](https://supabase.com/docs/guides/database/functions).

## 초기에 정리할 답변 데이터

| 항목 | 현재 확인한 내용 | 실제로 채울 정보 |
|---|---|---|
| 포트폴리오 | 관광 조사·기획·제작·최종 프로젝트 구조 | 대표 프로젝트명, 한 줄 소개, 기간, 대상, 상세 링크 |
| 개인 역할 | 구체적 기여도 미등록 | 개인/팀 작업 구분, 담당 업무, 기여 범위 |
| 제작물 | 카드뉴스·영상 갤러리에 예시 제목·날짜 존재 | 실제 제목, 표지, 게시일, 원본 링크, 공개 여부 |
| 제작과정 | 조사 → 기획 → 제작 → 공유 흐름 | 작품별 기획 의도, 조사 근거, 사용 도구, 작업 기간 |
| 문제 해결 | 상세 경험 미등록 | 어려움, 시도, 해결책, 전후 변화 |
| SNS 성과 | 조회 수·참여율·순위가 예시 | 실제 수치, 측정 기간, 집계 기준, 근거 링크 |
| 최종 프로젝트 | 프로젝트명·팀·기간·결과물 자리표시자 | 실제 프로젝트 개요, 팀 구성, 결과물 |
| 브랜드 | 워드마크·컬러 설명 존재 | 이름의 의미, 확정 브랜드 스토리 |
| 서비스 | Hidden Spot 소개·체험 링크 존재 | 운영 범위와 공개 가능한 확정 설명 |
| 문의 | SNS 링크 존재, DB 미연결 | 프로젝트 URL·공개 키, 개인정보 처리자·문의처·보유 기간, 회신 운영 기준 |

미확정 항목은 챗봇이 사실처럼 안내하지 않고 등록 준비 중으로 답변하도록 구성되어 있습니다. 실제 답변을 확정하면 JSON에서 준비 중 문구를 교체하세요.
