# OVE 챗봇 관리자

## 현재 상태

관리자 화면, 실제 챗봇 엔진을 사용하는 초안 미리보기, 초안·게시 버전·문의용 DB 스키마와 공개 챗봇 연동을 구현했습니다. 2026-10-26 `ove-homepage-admin` Supabase 프로젝트를 생성하고 문의·관리자 스키마를 적용했습니다. 공개 연결 설정을 등록했으며, Auth 관리자 계정 생성·권한 등록 및 첫 게시 검증은 진행 중입니다. 문의 접수 활성화에는 운영자 개인정보 안내 값이 필요합니다. 요청한 관리자 아이디는 `admin`입니다. 비밀번호는 Supabase Auth에만 설정하며 HTML·JavaScript·Git 저장소에서 비교하거나 저장하지 않습니다.

## 연결 순서

1. 사용할 Supabase 무료 프로젝트를 생성합니다. 계정 접속과 프로젝트 설정은 사용자의 승인이 필요합니다.
2. SQL Editor에서 `supabase/chatbot-inquiries.sql` → `supabase/chatbot-admin.sql` 순서로 적용합니다. 기존 문의를 삭제하지 않습니다.
3. Authentication → Users → Add user에서 `admin@ove.example` 계정을 만들고, 사용자가 요청한 초기 비밀번호를 입력합니다. 이메일은 로그인 ID `admin`을 인증 서버에 연결하기 위한 식별자이며 메일 발송용이 아닙니다. 이메일 확인 상태를 활성화합니다. 비밀번호 정책이 달라 거절되면 임의로 다른 비밀번호를 확정하지 않습니다.
4. SQL Editor에서 `supabase/chatbot-admin-bootstrap.sql`을 실행합니다. 이 이메일의 Auth 사용자 ID만 `chatbot_admins`에 등록합니다. 일반 회원이 로그인해도 관리자 권한은 생기지 않습니다.
5. 프로젝트 URL과 공개용 publishable/anon key를 `data/chatbot-config.json`의 `supabaseUrl`, `publishableKey`에 넣습니다. `adminEmail`은 위 이메일과 일치시킵니다. service_role/secret key는 브라우저 설정이나 Git에 넣지 않습니다.
6. 실제 문의 접수를 활성화하려면 같은 파일의 `privacy.controller`, `privacy.contact`, `privacy.retention`에 운영자가 확정한 처리자·개인정보 문의처·보유 기간을 입력합니다. 값이 비어 있으면 기존 문의 양식은 전송 준비 중 상태를 유지합니다.
7. GitHub에 설정 파일을 반영하고 `/homepage/admin.html`에 접속합니다. `admin`과 설정한 비밀번호로 로그인합니다.
8. 처음 로그인하면 기존 `data/chatbot.json`의 등록 데이터를 불러옵니다. 초안 저장 → 미리보기에서 실제 대화 확인 → 최종 게시 → 최종 게시 확인 순서로 첫 게시 버전을 만듭니다.
9. 공개 홈페이지를 새로 열어 내용과 문의 동작을 확인합니다. 본인 동의로 테스트 문의를 남기고 관리자 ‘접수 문의’에서 조회·상태 변경을 확인합니다.

## 편집과 게시

- 항목별 답변, 대표 질문, 키워드, 다음 버튼과 문의 양식을 수정합니다. 제목·메뉴·문의 공통 문구도 수정할 수 있습니다.
- 전체 JSON 가져오기·내보내기는 챗봇 안내 데이터만 대상으로 합니다. 문의 개인정보나 인증 토큰은 포함하지 않습니다.
- 초안 저장은 서버 초안만 갱신합니다. 공개 홈페이지는 초안을 읽지 않습니다.
- 미리보기는 **같은 챗봇 코드**를 사용합니다. 공개 사이트의 대화 기록과 분리하며 문의는 실제로 전송하지 않습니다.
- 초안 변경 후에는 저장·미리보기를 다시 거쳐야 게시 버튼을 사용할 수 있습니다. 서버도 현재 초안 revision과 미리보기 확인 revision을 비교합니다.
- 최종 게시 시 저장된 초안, 현재 게시 버전, 미리보기 확인 상태를 서버 트랜잭션으로 검사합니다. 오래된 창의 저장·게시·복원 요청은 충돌로 거절합니다.
- 최종 게시 확인 버튼까지 누르면 새 게시 버전이 생기고 공개 포인터가 바뀝니다. 새로 열거나 새로고침한 홈페이지가 그 버전을 읽습니다. 이미 열려 있는 대화는 새로고침 전까지 기존 데이터를 사용합니다.
- 이전 게시 버전을 ‘초안으로 불러오기’ 하면 공개 내용은 그대로이며, 다시 미리보기·최종 게시해야 복원 내용이 공개됩니다. 과거 게시 버전은 수정·삭제하지 않습니다.
- 게시 요청의 응답을 못 받았다면 무조건 재전송하지 말고 서버 초안을 다시 불러와 현재 게시 버전을 확인합니다. 중복 요청이나 오래된 게시 포인터로 인한 중복 게시를 차단합니다.
- 다른 브라우저에서 저장한 초안과 충돌하면 우선 편집 내용을 다운로드한 뒤 서버 초안을 다시 불러옵니다.

## 로그인·데이터 접근

- 비밀번호 검사는 Supabase Auth가 수행합니다. 로그인 후에도 모든 관리 RPC와 문의 테이블은 DB 관리자 명단으로 권한을 다시 검사합니다.
- 관리자 페이지의 로그인 화면 자체는 공개 URL이지만 초안·이력·문의 데이터는 인증된 관리자만 읽습니다. 페이지를 숨기는 것만으로 보호하지 않습니다.
- 익명 방문자는 현재 **게시된 데이터 1개**만 읽을 수 있고, 동의한 문의는 쓰기 전용 RPC로만 접수합니다. 초안·게시 이력·문의 목록을 직접 조회할 권한이 없습니다.
- 문의 상태만 새 문의/처리 중/완료로 수정할 수 있습니다. 이름·이메일·문의 원문을 관리 화면에서 덮어쓰지 않습니다.
- 인증 토큰은 관리자 페이지 메모리에서만 사용합니다. localStorage/sessionStorage에 관리자 토큰이나 문의 목록을 저장하지 않습니다. 새로고침하거나 로그인이 만료되면 다시 로그인해야 합니다. 로그아웃 시 화면의 문의·초안과 미리보기를 지웁니다.
- 공개 챗봇의 JSON은 원래 공개 안내 데이터입니다. DB 연결 전·장애 시에는 검증된 기본 안내 파일을 사용합니다. 문의 DB 연결 전에는 과거 문의가 서버에 쌓였다고 표시하지 않습니다.
- GitHub Pages를 계속 사용합니다. 별도 Sites 배포나 서비스 교체를 하지 않습니다.

## 파일

- `admin.html`, `css/admin.css`, `js/admin.js`: 관리자 로그인·편집·버전·문의 화면.
- `admin-preview.html`, `js/chatbot-preview-bridge.js`: 같은 출처의 관리자 부모창에서만 초안을 받는 미리보기.
- `js/chatbot-schema.js`: 안내 그래프·필수 문구·링크 검증.
- `js/chatbot.js`: 최초 기본 파일 + 서버 게시 버전 로딩, 문의 접수, 미리보기에서 전송·기록 저장 차단.
- `supabase/chatbot-admin.sql`: 관리자 권한, 초안, 게시 이력과 게시/복원 트랜잭션, 문의 RLS.
- `supabase/chatbot-admin-bootstrap.sql`: Auth에 만든 초기 관리자의 권한 등록. 비밀번호 없음.
- `supabase/chatbot-inquiries.sql`: 기존 문의 저장용 RPC 및 테이블.

## 검증과 한계

실제 서비스 계정과 분리된 로컬 PostgreSQL(PGlite)에서 마이그레이션과 익명/일반 회원/관리자 권한을 테스트합니다. 브라우저 검사는 임시 인증 응답과 실제 SQL 함수를 연결한 로컬 서버에서 수행합니다. 이 검증은 아직 만들지 않은 Supabase 운영 프로젝트의 계정·설정·네트워크 검증을 대신하지 않습니다.

```sh
node scripts/test_chatbot.cjs
PGLITE_MODULE=/absolute/path/to/@electric-sql/pglite/dist/index.cjs node scripts/test_admin_db.cjs
```

기존 챗봇 테스트에 공개 게시 버전 선택과 잘못된 게시 데이터의 기본 파일 복구를 추가했습니다. PostgreSQL 검사는 익명/비관리자 조회 거절, 관리자 자기 승격 차단, 문의 개인정보 보호, 동의 접수 중복 방지, 상태 컬럼 외 변경 차단, 초안 비공개, 미리보기 전 게시 거절, 충돌 검사, 게시 이력 및 복원 시 공개 버전 유지 등을 확인합니다. 운영 프로젝트 연결 후에는 실제 Auth 로그인·미리보기·게시·문의 접수를 다시 확인해야 합니다.
