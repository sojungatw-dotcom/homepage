# 홈페이지 기능 수정 — 2026-10-26

시작 상태: main `81237f4`, 수정된 추적 파일 없음. 기존 미추적 `REVIEW.md`는 그대로 보존했습니다. 관리자 인증·게시 기능과 기존 페이지 구성·메뉴·팔레트는 유지합니다.

## 기능별 반영

1. **관광 조사표 스크롤** — 오른쪽 grid 패널의 최소 높이를 0으로 제한하고 콘텐츠 행을 `minmax(0,1fr)`로 설정했습니다. 내용이 창을 밀어내는 대신 상세창 안에서 스크롤됩니다. 스크롤 영역의 키보드 접근과 포커스 순환도 보완했습니다.
2. **방문자 후기** — 장소별 닉네임·소감 입력 및 공개 동의, 접수 완료/실패 안내, 공개 후기 조회·더 보기, 관리자 ‘방문자 후기’ 탭을 추가했습니다. 기존 조사 자료는 실제 접수 후기와 구분해 보존합니다. 접수된 후기는 확인 대기로 저장하며 관리자가 공개 상태로 바꾼 후기만 보여줍니다. 문의와 다른 테이블을 사용하고 익명·비관리자에게 미승인 후기를 노출하지 않습니다.
3. **챗봇 콘텐츠 카드** — `data/content-catalog.json`의 공개된 카드뉴스·영상만 표지·제목·설명·상세 링크가 있는 카드로 표시합니다. 콘텐츠/카드뉴스/영상 선택에서 사용할 수 있으며 기존 대화·버튼과 동일 엔진의 관리자 미리보기를 유지합니다. 기획 중인 작품은 공개 작품에 포함하지 않습니다.
4. **SNS 채널 바로가기** — 기존 Instagram·YouTube 공식 링크를 본문 상단에 로고·채널명과 함께 추가했습니다.
5. **콘텐츠 표지** — 공개 Instagram 카드뉴스의 첫 슬라이드를 로컬 파일로 저장해 부산국제영화제·범어사 표지에 적용했습니다. 부산 지명 이야기·부산 영화 포스터 만들기는 최종 원본이 없어 기획 상태를 명시한 SVG 소개 표지를 사용합니다. 새 SNS 게시가 완료됐다는 의미가 아니며 기존 제작 상태와 게시 링크는 유지합니다.

## 연결 및 검증 상태

- 사용자 승인 후 `supabase/visitor-reviews.sql`을 운영 프로젝트에 적용했고 실제 접수를 확인했습니다. `reviewsEnabled`는 true입니다. 이때 만든 기능 확인용 후기 1건은 실제 방문 후기와 구분해 비공개 처리했습니다. 이후 관리자 탭 검증은 운영 프로젝트와 연결되지 않는 로컬 PostgreSQL에서만 진행했습니다.
- 로컬 서버: `http://127.0.0.1:8766/report.html`.
- 사용자가 로컬 페이지를 연 뒤 100% 배율(zoom 1, viewport scale 1)의 데스크톱 1440×900 및 모바일 390×844에서 스크롤 끝부분 도달을 확인했습니다. 카드뉴스 표지·필터, 챗봇 카드 미리보기, SNS 로고 링크와 모바일 가로 넘침도 검증했습니다.
- 운영자명·개인정보 문의 연락처가 비어 있는 기존 제작 문의 설정은 임의로 채우지 않았습니다. 방문자 후기는 공개용 닉네임과 소감만 입력하며 실명·연락처를 적지 않도록 안내합니다.

## 관리자 후기 탭 최종 검증

- 별도 테스트 서버 `127.0.0.1:8879`는 인메모리 PGlite와 가짜 테스트 인증만 사용합니다. 운영 Supabase나 운영 계정에 접속하지 않습니다. 기존 `8878` 테스트 서버 데이터도 초기화하지 않았습니다.
- 후기 확인 대기 → 관리자 승인 → 공개 조회 → 복구 가능한 삭제 → 공개 목록 제외 → 삭제됨 목록 → 원문 복구 → 확인 대기 복귀를 브라우저와 API로 검증했습니다.
- 익명과 일반 로그인 회원의 승인·삭제·복구를 DB에서 차단합니다. 원문 변경과 물리적 DELETE 권한도 주지 않습니다. 로그아웃 시 후기 카드가 비워지고 네 개 관리자 탭의 키보드 이동도 정상 동작합니다.
- 모바일에서 관리자 탭 이름이 끊기던 표시를 수정했습니다. 390px 화면에서 탭 버튼은 한 줄이며 가로 넘침이 없습니다.
- 삭제 기능이 기존 코드에 없어서 `supabase/visitor-reviews-deletion.sql`을 추가했습니다. `deleted_at`을 기록해 원문을 보존하며 복구해도 자동으로 공개하지 않습니다. 반복 적용 시 기존 데이터가 보존되는 테스트도 통과했습니다.
- **운영에는 삭제용 추가 SQL을 적용하지 않았습니다.** `reviewDeletionEnabled`는 false입니다. 기존 스키마에서도 조회·승인은 계속 동작하고 삭제 버튼은 노출하지 않습니다. 운영 적용 시 추가 SQL 반영과 권한 확인 후에만 이 값을 true로 변경합니다.
- 실행 가능한 테스트 환경과 API 검사는 `scripts/serve_review_test.cjs`, `scripts/test_review_api.cjs`로 보존했습니다. `PGLITE_MODULE`을 설치된 PGlite 모듈 경로로 지정해 실행하며 로컬 관리자 테스트 비밀번호는 `test-only`입니다. 실제 운영 비밀번호와 관계없습니다.
- 남은 항목은 운영 삭제용 SQL 배포·활성화, 기획 콘텐츠 2건의 최종 이미지, 기존 제작 문의에 필요한 운영자명·연락처입니다. 검증 범위 내 재현되는 기능 오류는 없습니다. 브라우저 기본 삭제 확인창은 자동 제어가 응답하지 못해 사용자가 확인 버튼을 누른 뒤 테스트를 마쳤습니다.

## 제공된 최종 미디어 적용

- 부산국제영화제 6장·범어사 8장을 사용자 제공 최종 JPG로 교체했습니다. 각 카드 양옆의 < > 버튼으로 콘텐츠 페이지 안에서 장을 넘깁니다. 팝업은 사용하지 않습니다. 카드별 독립 상태·앞뒤 버튼·방향키 이동을 확인했습니다. 14개 파일은 제공된 원본과 SHA-256이 일치합니다.
- 국밥 브이로그(27.2초)·UPSIDE DOWN(9초)은 사용자 제공 MP4로 교체했습니다. 원본 파일은 보존하고 H.264/AAC·최대 긴 변 1920px의 웹용 사본을 만들었습니다. 크기는 각각 84,466,461 → 12,710,545 bytes, 29,673,392 → 7,403,434 bytes입니다. 파일 앞에 재생 정보가 있는 fast-start MP4입니다.
- 기존 콘텐츠 카드 안에서 직접 재생하며 자동 재생은 하지 않습니다. 초기 전체 영상 다운로드를 피하도록 preload=none을 적용했습니다. 두 영상의 실제 재생·원래 화면 비율, 중복 재생 방지, 필터 변경 시 일시정지를 확인했습니다.
- 기존 SNS 게시 링크·게시일·기획 상태·나머지 여행 시작 영상은 유지했습니다. 챗봇은 같은 콘텐츠 목록의 교체된 표지를 사용합니다.
- 1440×900 및 390×844에서 페이지 내 카드 넘기기·이미지 로딩·버튼 접근과 영상 재생을 검증했습니다. 부국제 6장·범어사 8장 모두 마지막 장까지 이동하며 첫·마지막 장의 경계 버튼을 비활성화합니다.

- 콘텐츠 카드의 별도 ‘최종 영상 파일’ 링크는 제거했습니다. Instagram·YouTube 게시물 링크는 접근 가능한 이름과 44px 클릭 영역을 가진 SVG 로고 버튼으로 표시합니다. 카드뉴스 좌우 화살표는 배경·테두리 없이 투명하게 표시합니다. 기존 재생용 MP4와 게시물 URL은 유지합니다.
